# echecker — дизайн

Дата: 2026-11-12

## Мета

Android-застосунок із віджетом, що показує, чи є зараз світло для обраної черги
за графіком відключень ЗАПОРІЖЖЯОБЛЕНЕРГО. Графіки публікуються в публічному
Telegram-каналі https://t.me/Zaporizhzhyaoblenergo_news.

## Функціональні вимоги

1. Користувач обирає свою чергу (1.1, 1.2, …, 6.2).
2. Віджет 2×1 показує поточний статус і час наступної зміни.
3. Якщо на сьогодні графіка нема — показати «Відключень не заплановано».
4. Екран застосунку: вибір черги, інтервали на сьогодні та на завтра (якщо опубліковано),
   історія графіків за минулі дні, час останнього оновлення, кнопка «Оновити».
5. Історія = архів **запланованих** відключень для обраної черги (фактичні відключення
   застосунок не бачить). Накопичується з моменту встановлення + одноразовий
   backfill останніх 30 днів.

## Поза обсягом

Сповіщення, iOS, кілька черг одночасно, фактичні відключення, інші області/канали.

## Стек

Kotlin, Jetpack Compose (UI), Jetpack Glance (віджет), WorkManager, Room, DataStore,
OkHttp, Jsoup. Сервера немає.

## Джерело даних

Публічний веб-перегляд каналу `https://t.me/s/Zaporizhzhyaoblenergo_news` — HTML без
авторизації, ~20 останніх постів на сторінку. Старіші пости — `?before=<postId>`.
Текст поста: елемент `.tgme_widget_message_text`, id поста — атрибут `data-post`
(`Zaporizhzhyaoblenergo_news/<id>`), дата — `time[datetime]`.

Ризик: зміна верстки сторінки Telegram потребуватиме оновлення `ChannelFetcher`.

## Архітектура

Один модуль `app`.

| Компонент | Відповідальність | Залежності |
|---|---|---|
| `ChannelFetcher` | Завантажити сторінку (опційно `before`), повернути `List<RawPost(id: Long, publishedAt: Instant, text: String)>` | OkHttp, Jsoup |
| `ScheduleParser` | Чиста функція `parse(text): Schedule?`; `Schedule(date: LocalDate, queues: Map<Queue, List<Interval>>)`; `null` якщо пост не графік | — |
| `ScheduleRepository` | Зберігання в Room; для кожної дати лишається графік з найбільшим `postId`; `Flow` графіка за датою та за діапазоном дат; час останнього успішного синку | Room, Fetcher, Parser |
| `PowerStatusCalculator` | Чиста функція `(today: Schedule?, tomorrow: Schedule?, queue, now: ZonedDateTime) → PowerStatus` | — |
| `SettingsStore` | Обрана черга | DataStore |
| `SyncWorker` | fetch → parse → save → `PowerWidget.updateAll()`; режим backfill | Repository |
| `PowerWidget` | Glance-віджет 2×1, тап відкриває застосунок | Calculator, Repository, Settings |
| `MainScreen` (Compose) | Вибір черги, Сьогодні, Завтра, Історія, «Оновити» | Repository, Settings |

### Моделі

- `Queue(group: Int, sub: Int)` — 1..6 × 1..2, відображення `"N.M"`.
- `Interval(start: LocalTime, endMinuteOfDay: Int)` — кінець як хвилина доби (0..1440),
  щоб коректно представити `24:00`.
- `PowerStatus`:
  - `On(nextOffAt: ZonedDateTime?)` — `null` = відключень далі не заплановано;
  - `Off(nextOnAt: ZonedDateTime)`;
  - `NoScheduleToday`;
  - `NoData`;
  - `QueueNotSelected`.

## Потік даних

1. **Перший запуск:** вибір черги → one-time `SyncWorker` у режимі backfill: гортати
   `?before=` назад, доки дата постів не стане старшою за 30 днів, максимум 20 сторінок.
2. **Періодичний синк:** `SyncWorker` кожні 30 хв (constraint: мережа) завантажує першу
   сторінку, парсить, upsert-ить у Room, оновлює віджет. Помилка → `Result.retry()`
   з експоненційним backoff; кеш не змінюється.
3. **Віджет:** читає графіки на сьогодні/завтра + чергу, рахує статус, рендерить.
   Після рендера ставить неточний `AlarmManager`-будильник на момент наступної зміни
   статусу, який викликає перерендер з кешу (без мережі).
4. **UI:** підписка на `Flow` з Room; «Оновити» → one-time `SyncWorker`.

## Парсинг

- Пост є графіком, якщо містить `Графік відключення на DD.MM.YYYY`. Інші пости ігноруються.
- Черга: `Черга N.M`. Рядки `з HH:MM до HH:MM` належать останній знайденій черзі.
- `24:00` = кінець доби (1440).
- Черга, відсутня в пості, = відключень не заплановано.
- Перекриття/суміжні інтервали в межах черги об'єднуються.
- Префікс «ОНОВЛЕННЯ!» не впливає на парсинг; пріоритет визначає більший `postId`.

## Розрахунок статусу

- Увесь час — у зоні `Europe/Kyiv`, незалежно від зони телефону.
- Інтервали сьогодні та завтра перетворюються на абсолютні проміжки й об'єднуються,
  тому `23:30–24:00` сьогодні + `00:00–01:00` завтра = один проміжок до 01:00 завтра.
- Якщо `now` у проміжку → `Off(кінець проміжку)`; інакше → `On(початок наступного
  проміжку або null)`.
- Графіка на сьогодні нема, але синк був → `NoScheduleToday`. Синку ніколи не було → `NoData`.

## Стани віджета

| Ситуація | Текст |
|---|---|
| `On(t)` | «💡 Світло є · вимкнуть о HH:MM» |
| `On(null)` | «💡 Світло є · відключень більше нема» |
| `Off(t)` | «🌑 Світла нема · увімкнуть о HH:MM» (+ «завтра», якщо інша доба) |
| `NoScheduleToday` | «Відключень не заплановано» |
| `NoData` | «Немає даних · відкрийте застосунок» |
| `QueueNotSelected` | «Оберіть чергу» |
| Останній успішний синк > 3 год тому | додатково дрібно «оновлено о HH:MM» |

## Тестування

- `ScheduleParser` — юніт-тести на реальних текстах (приклад нижче як фікстура),
  пост-«ОНОВЛЕННЯ», пост без графіка, черга без інтервалів, `24:00`.
- `PowerStatusCalculator` — табличні тести: до/в/після інтервалу, межа 24:00,
  склейка через північ, об'єднання перекриттів, порожній графік.
- `ChannelFetcher` — на збереженому HTML-знімку сторінки, без мережі.
- `ScheduleRepository` — Room in-memory: для дати виграє більший `postId`.
- Віджет та UI — ручна перевірка на емуляторі.
